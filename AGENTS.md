# Проект

Это веб-приложение для расчёта стоимости натяжных стен.

Основная структура данных:

Объект → Комнаты → Стены.

Не менять эту иерархию без прямого указания пользователя.

# Основные принципы интерфейса

- приложение в первую очередь используется с телефона;
- интерфейс должен быть простым и быстрым;
- не показывать все параметры объекта одной длинной формой;
- на экране объекта показывать компактные карточки комнат;
- на экране комнаты показывать компактные карточки стен;
- подробное редактирование выполняется внутри конкретной стены;
- не усложнять интерфейс без прямого запроса пользователя;
- существующий дизайн не менять глобально при функциональных доработках.

# Расчёт стены

Для каждой стены есть:

- ширина;
- высота;
- площадь;
- материал;
- четыре стороны профиля;
- дополнительные элементы;
- звукоизоляция.

Площадь стены рассчитывается автоматически из ширины и высоты.

Профиль выбирается независимо для:

- верха;
- низа;
- левой стороны;
- правой стороны.

Верх и низ используют ширину стены.

Левая и правая стороны используют высоту стены.

Стоимость каждого профиля рассчитывается как длина × цена за погонный метр.

# Прайс

Пользователь не вводит цены вручную.

Все цены берутся из `data/prices.json`.

Расчётная логика должна ссылаться на позиции прайса по `id`.

Не хранить названия или цены товаров вручную внутри компонентов интерфейса или чертежа, если они уже существуют в прайсе.

Добавление новой позиции в прайс по возможности не должно требовать изменения расчётной логики.

# Состав стоимости

Основные группы стоимости:

1. Материал
2. Профили
3. Дополнительные элементы
4. Звукоизоляция

Итоги должны корректно суммироваться на уровнях:

Стена → Комната → Объект.

# Дополнительные элементы

В текущем MVP используются:

- подрозетники / выключатели;
- внутренние углы;
- внешние углы;
- звукоизоляция.

Архитектура должна позволять в дальнейшем добавлять новые элементы.

# Чертёж стены

Чертёж является схематичным видом стены спереди.

Он должен:

- сохранять пропорции стены;
- показывать размеры;
- показывать выбранные профили каждой стороны;
- использовать данные прайса для названий профилей;
- поддерживать визуальное отображение дополнительных элементов.

Сейчас не требуется полноценный CAD-редактор.

Архитектуру чертежа не делать тупиковой: позднее планируется ручное размещение подрозетников, выключателей и других элементов по координатам.

# Хранение

Пока расчёты сохраняются через `localStorage`.

Не добавлять серверную базу данных или авторизацию без прямого запроса.

# Публикация

Приложение публикуется через GitHub Pages из репозитория `stretch-walls-calculator`.

Пути к CSS, JavaScript, JSON и другим ресурсам должны корректно работать при размещении сайта в подпапке `/stretch-walls-calculator/`.

Не использовать абсолютные пути от корня домена, если это ломает GitHub Pages.

# Разработка

При каждой функциональной доработке:

- не переписывать работающие части без необходимости;
- сохранять обратную совместимость текущих сохранённых расчётов, если возможно;
- добавлять или обновлять тесты для новой расчётной логики;
- запускать все существующие тесты;
- проверять сборку;
- проверять `git diff --check`;
- исправлять найденные ошибки до завершения задачи.

Не настраивать GitHub CLI, `git remote`, токены или GitHub-аутентификацию внутри среды Codex.

Не добавлять функции, которых пользователь не просил.

При неоднозначности бизнес-логики не придумывать правило самостоятельно — оставить существующее поведение или явно указать вопрос пользователю.

Перед выполнением задачи сначала прочитать `docs/PRODUCT.md`.
